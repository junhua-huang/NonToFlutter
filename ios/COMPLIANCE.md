## 配置与发布检查

1. 填写 `Nonto/Resources/Compliance.json` 的真实信息。`processorSummary` 应包含每个实际处理方的名称/联系方式或政策入口、数据种类、用途及处理方式；`retentionSummary` 应区分账号、消息、媒体、日志、审核证据和备份及注销的处理安排。
2. 实现并完成上述服务端/运营验证，再逐项设置 `verification`，并保留测试或运行证据。`releaseReviewed` 仅在完成后的政策经过运营方核对时设置，不应把改布尔值当作完成事项。
3. 将渲染后的完整政策发布到填写的公开 HTTPS 页面，核对客户端显示内容。政策和配置变化会使已有本机同意版本失效。
4. 执行 `python3 ios/scripts/check_compliance.py --release`，解决所有阻断项后再 Archive。当前检查失败是对尚缺资料的真实反映；普通 `xcodebuild build/test` 仍可开发验证。
5. 用新安装设备抓包确认拒绝时无业务网络请求、同意后才恢复；关闭系统通知仍能使用文字服务；验证撤回、重新同意、注销、另一账号数据隔离、举报处理及屏蔽。云端 XCTest 的模拟网络测试不等于这项真机和生产验收。

本次代码使用配套 Python 分支中已存在的 HTTP Bearer 与 WebSocket 首帧认证；上线前必须核实实际部署支持这些契约。本次未修改或部署 Python 服务，没有对真实账号执行删除或举报。
