# 南图 · 原生 iOS

分支 `ios` 从 `master` 的 `c24b5a3` 创建。`ios/Nonto.xcodeproj` 是独立的 SwiftUI 应用；无需安装 Flutter 或 CocoaPods；Xcode 自动解析固定版本的 Lottie 4.6.1。原 Flutter 代码保留用于其他平台及核对接口。

## 设计和系统能力

- iOS / iPadOS 26 起，Xcode 26 或更高版本。
- 保留原品牌蓝 `#1D9BF0`、点赞粉 `#F91880` 和现有 N 图标。
- 原生 `TabView`、`NavigationStack`、工具栏、表单、菜单和系统弹窗采用 Liquid Glass；操作按钮使用 `.glass` / `.glassProminent`，悬浮输入栏使用 `.glassEffect`。内容层保持可读，遵从系统的浅深色、动态字体和降低透明度设置。
- 网络：`URLSession` 和 `URLSessionWebSocketTask`。
- 凭据：Keychain，解锁后可访问且不随设备迁移。
- 存储：系统 Caches 目录中的账号独立 JSON 快照、UserDefaults 偏好/文字草稿/待发送记录。缓存带文件保护；与 Flutter 的数据库独立，已有服务端数据直接读取。
- 图标：SF Symbols；媒体：PhotosPicker、AVPlayer、系统分享面板。
- 通知：原生 APNs 注册、设备与账号绑定、令牌更新、退出解绑、通知点击跳转、前台去重、角标，以及本地/远程测试入口。启用真实推送需要先部署配套后端 `ios` 分支并配置苹果推送凭据，见 [APNs 接入](APNS.md)。

## 构建检查（Windows 无需 Xcode）

推送 `ios` 会自动运行 `.github/workflows/native-ios.yml`：

1. 校验工程生成结果。
2. 在 macOS 上编译原生应用并运行 XCTest。
3. 额外编译 iPhone Release 目标（不签名）。
4. 上传日志、测试结果和模拟器应用，保留 7 天。

模拟器 `.app` 不能安装到 iPhone；这个流程也不会自动上传 TestFlight。

有 Mac 时可直接打开 `ios/Nonto.xcodeproj`，选择 Nonto scheme 和模拟器。命令行示例：

```sh
python3 ios/scripts/generate_project.py
xcodebuild -project ios/Nonto.xcodeproj -scheme Nonto \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  CODE_SIGNING_ALLOWED=NO test
```

实际模拟器名称以 `xcrun simctl list devices available` 为准。工程文件已提交，Python 脚本仅在增删 Swift 源码/资源后重跑；无额外 Python 依赖。

## 整体交互优化

- 列表滚动到底部自动续页，保留手动加载和失败重试；按失败请求重试原页，不把刷新失败误当作下一页。缓存加载失败时继续显示已有内容并标注缓存状态。
- 页面返回后 60 秒内复用已加载的列表与分页，减少重复刷新；下拉刷新、业务变更和实时更新仍会请求新数据。通知、好友、消息、社群、搜索结果使用各自的空状态文案。
- 个人主页的资料、筛选和动态使用同一个列表连续滚动，不再将屏幕拆成两个滚动区。
- 发布草稿同时保存文字、可见范围和展示身份，兼容旧文字草稿；输入停止或进入后台时保存，取消时可保留文字草稿或放弃。编辑修改和未保存媒体避免被手势意外关闭；发布期间冻结输入，账号切换后停止后续上传/发布。
- 评论发送期间继续输入的新文字和回复对象不会被上一条成功回执清空；回复评论自动聚焦。通知已读和删除在原列表就地更新，避免重置位置；已读请求失败不会阻断关联页面打开。
- 图片缩略图显示加载状态和点击重试，搜索校验提示始终可见；通知偏好加载失败可重试、加载完成前禁止修改，退出与密码修改显示进行中状态。

`UserExperienceTests` 覆盖重试页码、列表复用、缓存恢复、刷新期间已读覆盖及草稿账号/社群/引用隔离、可见范围恢复和旧草稿迁移。视觉布局、动态字体和实际手势仍需真机验收。

## 真机 / TestFlight

初始 Bundle ID 为 `online.nonto.native`。维护者应在苹果开发者账户中确认相应 App ID、App Store Connect 应用、Development Team 和签名描述文件，或先修改工程生成脚本中的 Bundle ID 再重新生成。需要云端签名上传时再配置该仓库的证书及 App Store Connect 凭据；不将这些凭据提交到代码。

云端内部测试的具体步骤见 [TestFlight 发布](TESTFLIGHT.md)。`TestFlight Internal` 是单独的手动请求流程，区别于上面的未签名编译验证。

## 后端契约

默认仍连接 `https://www.nonto.online/api` 与 `wss://www.nonto.online/ws`。可在 `APIClient` 初始化时注入其他地址以开发和测试。HTTP 使用配套后端已支持的 `Authorization: Bearer`，WebSocket 使用现有首帧 `auth`，连接 URL 不携带账号令牌；上线前需核实实际部署支持。令牌仅发送到自己的 API，COS 请求不携带应用凭据。跨域重定向被拒绝，401 只共享一次续期，并保留原始分页/筛选参数；账号变化后丢弃旧会话响应。

测试使用 URLProtocol 假服务器，不调用生产 API，也不创建、修改或删除真实账号/社群/动态。

### 稳定性与体验改进

- 聊天使用独立 `ChatStore`：按顺序持久化发送队列，失败重试保留请求 ID，发送确认不完整时保留待发送项；页面退出或进入后台时取消房间任务。
- 聊天草稿按账号和房间保存，输入时延迟 400 毫秒合并写入、离开时立即保存；阅读历史时显示新消息提示，避免被强制滚动；实时事件触发刷新，20 秒轮询补偿漏掉的事件。
- 聊天采用系统 `ScrollPosition` 保持历史阅读位置；连续消息按发送者分组，间隔 5 分钟或跨天显示时间，群聊显示姓名。输入栏支持多行、引用后聚焦和外接键盘 Command-Return 发送，并遵从减少动态效果设置。
- 照片/视频先在本地预览，确认后上传，可添加说明、取消或失败重试；保留原文字草稿。发送队列区分上传/发送中、等待前一条重试和失败，发送中的消息不可误标为已取消。
- 修复历史加载被实时刷新吞掉、历史确认首条成功后队列不继续、整页刚好 50 条仍显示加载入口，以及撤回后旧消息内容仍保留的问题。
- 分页刷新合并重复请求，重复记录更新内容并保持顺序，异常响应保留现有数据，重复页或不前进的游标停止继续加载。
- 动态点赞、编辑、删除局部更新，保留已加载页面；进行中的刷新不会覆盖刚完成的操作。
- 原生图片缩放与拖动、图片加载失败重试、后台照片降采样；视频离开前台时暂停。
- 修复密码重置提示消失、资料编辑重复初始化、清理缓存成功被显示为错误，以及登录后资料加载失败导致凭据丢失的问题。

`StateTests` 和 `ChatExperienceTests` 使用模拟 HTTP 响应覆盖上述状态与并发场景；仍需使用真实账号在真机验证服务端兼容性和交互细节。


## Noto 动态表情

聊天输入栏的笑脸按钮打开 881 个 Google Animated Noto Emoji，支持分类、中文/英文/emoji 搜索、动画预览、单独发送和按账号记录最近使用。发送表情保留正在编辑的文字草稿。

复用私信/社群聊天现有文字接口和持久化发件箱，发送标准 Unicode。支持的 1–3 个纯 emoji 消息展示为无底色动画；文字混排、未收录和超过三个的 emoji 保持文字显示，旧客户端也能正常阅读。

离线原始 Lottie JSON 和缩放的静态 PNG 预览保存为 `Nonto/Resources/NotoEmoji.zip.001`、`.002`，构建时拼接并通过系统 ditto 解压至派生资源目录。运行时不访问 Google。离屏/后台/关闭播放/系统减弱动态效果时显示静态预览。设置中的“表情资源与许可”提供 Google/CC BY 4.0、Unicode CLDR、Lottie/Apache 2.0 的署名及许可全文。

Swift Package 精确固定为 Airbnb 官方 lottie-spm 4.6.1；Package.resolved 包含提交版本。测试仅使用 iOS 27/iPadOS 27。资源脚本检查完整目录、原始哈希、预览、外部依赖和许可证；原生测试检查全部动画解码、Unicode 兼容、搜索、账号隔离，并输出选择器截图。
